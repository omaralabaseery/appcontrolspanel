# بيانات تجريبية في Firestore

العملية تضيف 8 مستخدمين و13 جهازًا و24 طلبًا/لوج وسجل إشعار محاكى، بإجمالي 46 مستندًا. لا تنشئ حسابات Firebase Authentication أو كلمات مرور أو FCM tokens ولا ترسل إشعارات حقيقية. استخدم جهازًا وحسابًا حقيقيين لاختبار تسجيل الدخول ووصول Push.

## قبل التنفيذ

- أصلح تحميل resources أولًا كما في DATABASE_SETUP_AR.md، ثم شغّل المشروع.
- فعّل Firestore في مشروع insta-11358 واتبع FIREBASE_SETUP.md لضبط صلاحيات السيرفر والأدمن.
- Web Config وحده لا يمنح الباك إند صلاحية الكتابة. لا ترفع مفتاح Service Account إلى GitHub ولا ترسله في المحادثة.
- يفضل مشروع اختبار منفصل. لو استخدمت نفس مشروع الإنتاج، ستدخل هذه السجلات في أرقام الإحصائيات حتى تحذفها.

## التنفيذ من Swagger

1. افتح http://localhost:8089/swagger-ui.html وسجّل Firebase ID token لحساب أدمن في Authorize.
2. نفّذ POST /api/admin/database/initialize مرة واحدة لإنشاء الإعدادات الناقصة.
3. نفّذ POST /api/admin/database/demo مع الجسم:

```json
{"projectId":"insta-11358"}
```

4. افتح لوحة التحكم، اضغط Connect Firebase وسجّل دخول حساب الأدمن ثم حدّث البيانات. وضع Demo في المتصفح يعرض عينات محلية ولا يقرأ Firestore.

كل مستند له testData=true وseedBatch=panel-demo-v1 ومعرف يبدأ seed_v1_. الأسماء تبدأ [TEST]. تكرار الطلب يضيف الناقص فقط ولا يغيّر الموجود أو سياسات النسخ والصيانة. المستخدمون الأونلاين التجريبيون يصبحون أوفلاين بعد انتهاء نافذة الخمس دقائق؛ لا توجد heartbeat حقيقية.

## إزالة البيانات قبل استقبال المستخدمين الحقيقيين

نفّذ DELETE /api/admin/database/demo بنفس الجسم. يحذف فقط المعرفات المعروفة التي تحمل علامتي الاختبار، ولا يحذف المستخدمين الحقيقيين أو الإعدادات أو سجل التدقيق. أي نشاط إضافي أنشأته يدويًا خارج هذه العينة يحتاج مراجعة منفصلة.

تعبئة البيانات ليست إثباتًا لجاهزية الإنتاج. يلزم اختبار صلاحيات الأدمن، روابط المتاجر الفعلية، تسجيل جهاز حقيقي، وصول Push، وHTTPS قبل الإطلاق.

## نطاق المرحلة الحالية

العينة مرتبطة بالمستخدم عبر uid؛ من Users & devices افتح View profile ثم View requests & feature activity لعرض نشاط المستخدم فقط. يوجد للمستخدم التجريبي الأول أمثلة نجاح فتح شاشة وفشل فتح تفاصيل طلب وخطأ عرض الملف الشخصي. هذه أحداث مصطنعة مكتوبة في حقول اللوج الحالية وليست مراقبة فعلية للموبايل. ربط تطبيق الموبايل وقاعدة البيانات الفعلية وتعديل الـschema مؤجل للمرحلة الثانية؛ لم نغيّر الـschema في هذه الإضافة.
